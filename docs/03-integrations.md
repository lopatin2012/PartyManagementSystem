# 03. Интеграции

## 1. «Честный Знак» (СУЗ / TrueAPI)

Сервисы (`app_cz/services/`):

| Сервис | Назначение |
| --- | --- |
| `suz_client` | Авторизация TrueAPI: auth key → session token → dynamic token; обновление токена |
| `true_api_client` | Обёртка над методами True API |
| `party_service` | Генерация/резервирование номеров партий, генерация УИП, синхронизация партий |
| `code_client` | Отчёт о нанесении (application report) |
| `code_sync` | Приём заданий и синхронизация кодов маркировки с внешним сервисом |
| `code_archive` | Архивация устаревших кодов |
| `reserve_monitor` | Мониторинг резерва и сгорания |
| `national_catalog_client` | Методы Национального каталога (ГИС МТ) |
| `rate_limit` | Ограничение частоты запросов к NK/True API |
| `nk_sync_state` | Межпроцессная блокировка и прогресс синхронизации НК |

Особенности:

- **Лимиты True API** учитываются в `rate_limit.py`: `/nk/product` — не более 10 запросов за
  5 минут, остальные методы НК — 10 запросов/с. Лимитер «размазывает» запросы равномерно.
- **СУЗ-токен** живёт 8 часов, обновляется автоматически (задача каждые 6 часов).
- **Синхронизация НК** сериализована между процессами (web и worker) через `NKSyncState`
  (row id=1, `SELECT ... FOR UPDATE`) — параллельный запуск возвращает 409. Есть heartbeat-таймаут
  (10 минут) и команда `python manage.py reset_nk_sync` для сброса зависшей блокировки.

## 2. «Молвест.Маркировка» (локальные серверы заводов)

Схема обмена — двусторонняя, устойчивая к сбоям.

### Push (внешний сервис → система)
- Внешний сервис периодически отправляет задание: `POST /cz/api/tasks/receive/`.
- Задание создаётся/обновляется по `uuid_str`/`uuid_task` (идемпотентно). Задания без UUID
  пропускаются как некорректные.
- Задания с локально сформированным УИП (`reserved_local`) внешний сервис досылает каждую минуту,
  пока система недоступна.

### Pull (система → внешний сервис)
- `sync_external_parties_and_codes` (раз в час) забирает задания, изменённые после метки
  синхронизации: `GET http://<ip>:<port>/task/api_task_external/?changed_since=...`.
- Метка **персональная для каждого завода** (`Factory.external_sync_changed_since`) и сдвигается
  только при успешной выгрузке. При сбое метка не меняется — окно будет повторено; сбой одного
  завода не влияет на остальные.
- При успехе метка сохраняется с зазором 5 минут (защита от гонок и расхождения часов).
- Коды забираются по заданию: `GET /codes/api/get_codes_by_task/?uuid_task=...`, возвращаются
  `sntins_camera` (нанесённые) и `sntins_printer` (в очереди печати), а при агрегации — ещё и
  структурированный `codes: [{code, level, parent_code}]`.
- «Факт» (`produced_quantity`) пересчитывается как число фактически нанесённых (APPLIED) кодов.
- Адрес сервера маркировки — из модели `Factory` (`ip_address`/`port_address`), определяется через
  линию → цех → завод.

### Надёжность
- Идемпотентный приём заданий (обновление по UUID).
- При ошибке синхронизации задача помечается FAILED и повторяется через 5 минут.
- Ручной полный запуск: `POST /cz/sync/all/` (выгрузка заданий + коды).

## 3. Национальный каталог (ГИС МТ)

- Синхронизация номенклатуры: `/nk/product` (резильентные батчи с рекурсивным разбиением при
  ошибке 400 на весь батч).
- Преобразование товаров НК → `Product` / `ProductPackaging` / `ProductSKU`
  (`app_factory/services/nk_sync_service.py`).
- Артикулы поставщика берутся из атрибута `Код товара в учетной системе поставщика`.
- Срок годности продукта берётся из атрибута `Срок годности` (дни); если он
  отсутствует/не распознан — ставится дефолт `100` дней.
- Готовность к производству определяется по состоянию карточки товара.

## 4. 1С (ERP / УХ / УПП)

- Взаимодействие через REST API системы (см. `04-api.md`).
- Типовые сценарии: получение справочников, проверка статуса одного УИП и списка УИП,
  список действующих УИП, поиск по коду/УИП.

## 5. Прочие внешние сервисы

- Адреса внешних сервисов (подпись, WMS, печать, СУП) — модель `config.ExternalService`.
- Проверка доступности сервисов (СУЗ, заводы, 1С) — панель статусов в шапке; результаты
  кэшируются на 30 секунд.
