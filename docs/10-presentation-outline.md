# 10. Презентация: структура и тезисы

Готовая презентация: `PartyManagementSystem_презентация.pptx` (в этой папке). Ниже — структура
и тезисы для слайдов и заметок докладчика.

## Слайды

1. **Титул.** «Молвест.СистемаУправленияПартиями» — единая платформа учёта УИП и кодов маркировки.
2. **Зачем это нужно.** Обязательная маркировка; разрозненные данные (MES/WMS/1С/Маркировка);
   ручные операции; нет единой истории; риск рассинхрона.
3. **Решение.** Единый «мастер» по УИП и кодам: генерация/резервирование, коды L1/L2/L3,
   двусторонняя синхронизация, API, аудит, надёжность.
4. **Ключевая ценность.** Единый источник правды, автоматизация, прослеживаемость, надёжность,
   прозрачность, готовность к росту.
5. **Ландшафт интеграций** (схема). MES/1С ↔ система ↔ Молвест.Маркировка/СУЗ/НК/WMS.
6. **Обмен с «Молвест.Маркировка».** Push + Pull; догон после недоступности; иерархия кодов;
   актуальный «Факт»; повтор через 5 минут.
7. **Жизненный цикл УИП.** draft → reserved → registered → closed → archived; повторное
   резервирование сгоревших.
8. **Что автоматизировано.** Резервирование, мониторинг резерва/сгорания, очистка/архивация,
   токены, справочники.
9. **Коды и агрегация L1/L2/L3.** Иерархия «родитель-потомок», поиск с раскрытием дерева.
10. **Единый API и поиск.** Интеграционный API для смежных систем; Swagger; публичные/админ методы.
11. **Надёжность синхронизации.** Персональная метка завода, повтор, идемпотентность, ручной запуск.
12. **Прослеживаемость и аудит.** `UIPStatusLog`, лента событий, история по коду/партии, рассинхрон.
13. **Безопасность и доступы.** Публичный контур — только чтение/приём; управление — за правами.
14. **Технологии и эксплуатация.** Стек, Docker, CI/CD, мультизаводность.
15. **Эффект в цифрах** (оценочно, на участок).
    - Резервирование: вручную ≈5 мин → автоматически ≈10 сек (до 30× быстрее).
    - Подстановка в отчёты: вручную ≈3 мин/партия → 0.
    - GTIN → продукт: ручной поиск ≈2 мин → мгновенно из справочника.
    - Экономия: ≈8 мин/партия; при 20 партиях/сутки ≈2,7 ч/сутки и ≈600 ч/год.
    - Ошибки/дубли: риск ручного ввода исключён; срывы сроков: 0 пропущенных УИП.
16. **Эффект для бизнеса.** Меньше ручного труда, меньше рисков, данные сходятся, быстрее решения,
    прозрачность, масштабируемость.
17. **Планы развития.** Техническое зрение, третий уровень агрегации (паллета/SSCC), аналитика, Redis.
18. **Финал.** «Единый, автоматизированный и надёжный контур маркировки».

## Заметки докладчика (кратко)

- Проблема не в маркировке как таковой, а в разрозненности и ручном труде вокруг неё.
- Ключевой аргумент надёжности: система и завод могут быть недоступны — данные не теряются.
- Цифры эффекта — оценочные и консервативные; при необходимости подставить фактические объёмы.

## Как пересобрать презентацию

Презентация собирается скриптом (python-pptx) по этому плану. Цифры и формулировки — в
`10-presentation-outline.md`. При изменении функционала обновляйте слайды 6, 8, 11, 13, 15–17.
